Factory Inventory Management System

A demo full-stack application: a Vue 3 single-page dashboard, a Python FastAPI service, and in-memory data loaded from JSON files. There is no database.

System architecture

Three tiers, all running locally. The browser talks directly to the API over HTTP (CORS enabled).

Data flow

How a filter change on the dashboard becomes updated numbers on screen.

User changes a filter FilterBar updates shared refs (period, warehouse, category, status) in the useFilters singleton.
View reacts The active view watches the filters and calls getCurrentFilters(), then the matching method in api.js.
Request is sent Axios issues a GET to localhost:8001/api/.... Filters set to "all" are omitted from the query string.
API filters in memory The FastAPI handler runs apply_filters and filter_by_month (months or quarters such as Q1-2025) over the lists loaded from JSON.
Response is validated Pydantic response_model checks the shape. Dashboard, spending and report endpoints return computed aggregates.
UI re-renders Raw results are stored in refs. Computed properties derive chart series, KPIs and tables, and Vue updates the DOM.

Design characteristics

Deliberate demo simplifications

  • No database; data resets on every server restart.
  • No authentication; the frontend auth composable is a client-side mock.
  • CORS allows all origins; suitable for local use only.
  • API base URL is hard-coded to localhost:8001.

Key conventions

  • Raw data lives in refs; everything derived is a computed property.
  • Inventory has no time dimension, so it ignores the month filter.
  • Pydantic models must be updated whenever the JSON structure changes.
  • Revenue goals: $800K per month, $9.6M year to date.

Gaps observed in the code

Findings from reading the source; worth knowing before extending the app.

Missing task endpoints. api.js defines getTasks, createTask, toggleTask and deleteTask (/api/tasks), but the backend has no such routes.
Missing purchase-order endpoints. api.js calls POST /api/purchase-orders and GET /api/purchase-orders/{id}. The backend defines the Pydantic models and loads the data, but registers no routes.
Unrouted view. Backlog.vue exists but is not registered in the router; backlog data surfaces through the dashboard modal instead.
Inconsistent API access. Reports.vue calls axios directly with a hard-coded URL instead of going through api.js.
No frontend tests. Only the backend has a pytest suite (tests/backend).
